## 1. 做了什么

在不调用任何 LLM / 付费 API 的前提下，量化多种上下文管理策略在同一 token 预算下，能否把「用户早先说过、后来可能更正过的事实」留在上下文里。

指标只测「正确信息是否还在上下文里」（上下文级召回），没有调用模型作答。召回是必要条件，不等于模型一定能答对。

### 设定

- 合成数据：1688 批发客户与德化陶瓷店客服的长对话。平均 580 条消息，约 1.3–1.4 万 tokens（tiktoken `o200k_base`）。
- 每个对话埋 12 个事实槽位（收货城市、釉色、数量、单价预算、发票抬头、交期、Logo 工艺、包装、电话、器型、税点、物流），另有 8 次「更正」（旧值作废）和 10 条干扰（例如「我朋友订的是 X，跟我们无关」）。
- 10 个固定随机种子（0–9）；预算 800 / 1500 / 3000 tokens。
- 三种难度：
  - A：模板化闲聊（闲聊句高度重复，事实句词汇稀有——容易，存在数据伪影）
  - B：多样化闲聊（闲聊里也大量出现城市/价格/釉色/单号等）+ 用槽位原词提问
  - C：多样化闲聊 + 改写式提问（问题不含槽位原词，如「这批货最后要发到哪里？」）

### 策略

- `full`：全量历史（基线）
- `window`：滑动窗口，只保留最近能装进预算的消息
- `summary`：滚动压缩。超预算时把最老 40 条与旧摘要做抽取式摘要（句子得分=平均 IDF，无领域规则；用来替代 LLM 摘要）。摘要占 60% 预算，最近窗口占其余
- `bm25`：最近窗口（40% 预算）+ BM25（jieba 分词）从更早历史按问题召回，填满预算
- `bm25+recency`：BM25 分数乘以时间衰减系数（偏向新消息）
- `notes`：结构化笔记（槽位→最新值，写入时覆盖旧值）+ 最近窗口。抽取规则由实验者按模板编写，代表「理想记忆写入」的上界，不代表真实 LLM 表现

### 指标

- 召回率：上下文里是否含该槽位的**最新正确值**
- 冲突率：同时还含有过期值或干扰值的比例（设定 B/C 中，闲聊也会偶然提到同一城市/价格，这个指标偏粗，只看相对趋势）

### 局限

- 没有 LLM 作答，只测上下文是否包含正确信息，不测模型在冲突信息下能否答对
- 合成数据、模板有限；摘要用抽取式近似，真实 LLM 摘要可能更好，也可能产生幻觉
- `notes` 策略是规则写入的上界，真实系统里的难点是「模型能否可靠地抽取与覆盖」，本实验没测

## 2. 结果怎么样

完整表格见同目录 `results.md`，逐条记录见 `results.json`。下面数字均来自本次运行。

### 设定 B（多样化闲聊 + 原词提问）

对话规模：平均 580 条消息，13039 tokens。

| 策略 | 预算 | 平均上下文 tokens | 召回率 | 冲突率 |
|---|---|---|---|---|
| full | - | 12459 | 100.0% | 70.8% |
| window | 800 / 1500 / 3000 | 752 / 1410 / 2855 | **38.3% / 48.3% / 65.0%** | 11.7% / 25.8% / 43.3% |
| summary（抽取式） | 800 / 1500 / 3000 | 582 / 1168 / 2137 | 83.3% / 90.8% / 95.0% | 36.7% / 51.7% / 62.5% |
| bm25 | 800 / 1500 / 3000 | 779 / 1465 / 2928 | **100% / 100% / 100%** | 70.8% ×3 |
| notes（上界） | 800 / 1500 / 3000 | 763 / 1436 / 2866 | **100% / 100% / 100%** | 25.0% / 36.7% / 52.5% |

滑窗在长对话里会系统性丢掉早期事实：预算从 800 翻到 3000，召回也只从 38.3% 升到 65.0%。按「事实最后一次陈述距今」分桶（预算 1500）时，滑窗近/中/远分别为 68% / 45% / 35%。

### 设定 C（多样化闲聊 + 改写提问）

窗口和摘要与问法无关，数字与 B 相同。检索则明显掉下来：

| 策略 | 预算 800 / 1500 / 3000 的召回率 |
|---|---|
| window | 38.3% / 48.3% / 65.0%（与问法无关） |
| summary | 83.3% / 90.8% / 95.0%（与问法无关） |
| bm25 | **34.2% / 44.2% / 56.7%** |
| bm25+recency | 40.0% / 46.7% / 60.0% |
| notes（上界） | **100% / 100% / 100%**（最小预算也是 100%） |

BM25 在原词提问下接近 100%，改写提问立刻掉到约 34–57%。瓶颈在问题与事实的词汇重叠。时间衰减对冲突率几乎没帮助。

### 设定 A（模板化闲聊，容易）

summary 在 1500/3000 预算下 100%、800 下 96.7%；window 为 17.5% / 23.3% / 37.5%；bm25 约 99–100%。与 B 对比说明：抽取式摘要在 A 上的好成绩，很大程度来自「事实句恰好词汇稀有」的数据伪影，换成更嘈杂的闲聊就掉到 83–95%。

### 结论（只对本合成任务成立）

1. **纯滑窗不够用。** 预算翻 4 倍，召回也只从约 38% 升到 65%。
2. **检索依赖词面匹配。** 原词提问接近满分，改写提问掉到约 34–57%。下一步可换本地中文嵌入模型或做混合检索再测。
3. **摘要和检索会带回过期值。** 冲突率常在 50–70%。知识更新必须在写入侧显式覆盖或版本化槽位，不能指望读取侧检索去分辨新旧。
4. **结构化笔记是上界。** 最小预算下也是 100% 召回，且冲突最低；但这是按模板规则写入的结果，不是真实 LLM 记忆的表现。

分词器附注（见 `tokenizer_note.txt`）：同一段 16316 字的中文对话，`o200k_base` 为 12813 tokens（1.27 字/token），`cl100k_base` 为 17641 tokens（0.92 字/token），相差约 38%。按字数估算预算不可靠。
